# dsh container: update @deepseek-ai/dsh to 0.2.0-rc.2

Date: 2026-10-10

## What

`dsh/package.json` now pins `@deepseek-ai/dsh` at `0.2.0-rc.2`, the current
`latest` dist-tag (the only newer release is the `0.2.1-alpha.2` prerelease).
`pnpm-lock.yaml` was regenerated with pnpm 12.4.2, the same version the
`Dockerfile` installs, so `pnpm install --frozen-lockfile` matches.

The `dsh` subproject is the only place the version is pinned; the image and
`dsh-prod` bin path
(`/app/node_modules/@deepseek-ai/dsh/lib/bin.js`) are unchanged.

## Breaking changes and fixes

### 1. Boot failed: native binding under a `noexec` `/tmp` (fixed)

0.2.0's `dsh-app-boot` now requires `node-addon-require-builtin@0.1.6`. At host
preparation it loads the prebuilt `.node`, copying it into
`os.tmpdir()/node-addon-native-custom-loader-<uid>` and mapping the copy
executable. Docker mounts the compose `tmpfs: /tmp` `noexec`, so the mapping
failed and dsh exited at boot with:

```
dsh: fatal uncaught exception: ... No usable native binding found for
node-addon-require-builtin-linux-x64-gnu (auto)
```

This was the only hard blocker; 0.1.5 did not use the addon.

Fix: the `Dockerfile` sets
`NARB_NATIVE_CACHE_DIR=$DSH_HOME/.cache/native-binaries`. The loader writes its
copy to that directory (an executable named volume) instead of `/tmp`. The
loader owns this variable; `NARB_DISABLE_NATIVE_CACHE=1` (load the prebuilt in
place) also works. Fixing the `tmpfs` mount with `exec` would work too, but would
weaken the container's noexec hardening.

`--ignore-scripts` remains safe: the platform package
`node-addon-require-builtin-linux-x64-gnu` ships the prebuilt binary, so no
compile step is needed.

### 2. Models-page provider edits were overridden by the home patch (fixed)

In 0.1.5 the Web **Models** page wrote provider config to `$DSH_HOME/settings.yaml`
(a user settings section merged per provider). In 0.2.0 it writes the active
profile's `cordis.patch.yml` (`config-editor.documentPath` is the profile patch).

dsh composes patches in the order: bundle patches, the profile's
`cordis.patch.yml`, the home-level `$DSH_HOME/cordis.patch.yml`, then `--patch`
overlays. A row patch replaces the whole `config`, so the `llm-pi-ai` row seeded
by `global-agent-config/cordis.patch.yml` silently discarded anything the Models
page saved for that row. Verified with `--dump-config`: a provider in the profile
patch disappeared behind the home seed.

Fix (chosen over seeding the profile patch at first boot): remove the duplicate
config surface. `global-agent-config/cordis.patch.yml` and its compose mount are
gone; providers are configured once from the Models page. This is not a loss of
zero-config keys: the installed pi-ai catalog already declares each provider's
`apiKeyEnv` (Vercel AI Gateway reads `AI_GATEWAY_API_KEY`), so a key in `.env`
is used as soon as the provider is added. Per-profile provider config on the
`dsh-home` volume survives `just recreate` / `just down`.

An existing 0.1.5 `$DSH_HOME/settings.yaml` is imported once into the profile
patch and renamed `settings.yaml.imported` on first 0.2.0 boot.

### 3. Profile manifest `patchReload` removed (no fix needed)

0.2.0 dropped `dsh.profile.patchReload`; HMR is now the `dsh-hmr` plugin row,
enabled by the base bundle whenever the launcher supplies `profileContext` (all
CLI profiles). Config watching keeps working. The key left in the persisted
`profiles/web/package.json` is ignored (only `dsh.profile.bundles` is read), so
no migration is required.

### 4. Larger image footprint (accepted)

0.2.0 adds `dsh-hmr`, `dsh-plugin-manager`, `dsh-skill-office` and an
experimental voice bundle, pulling in `@deepseek-ai/libreoffice-kit-wasm`
(~48 MB) and `sherpa-onnx-*` (~11 MB). `node_modules` grew from ~600 to ~668
lockfile entries. Optional features stay disabled unless selected.

## Verification performed

No Docker on this host, so the image was not built. The dependency update was
validated directly against the installed tree:

- `pnpm install --ignore-scripts` then `pnpm install --frozen-lockfile
  --ignore-scripts` both succeed with pnpm 12.4.2; `dsh --version` reports
  `0.2.0-rc.2`.
- `dsh --profile web --dump-config` with a scratch `DSH_HOME` composes cleanly,
  the base `llm-pi-ai` row is present, and a provider written to the profile
  patch (what the Models page writes) appears in the final config.
- `dsh web --no-open --port 0` boots and prints its token URL with (a)
  `NARB_NATIVE_CACHE_DIR` on an executable path and (b) `NARB_DISABLE_NATIVE_CACHE=1`,
  and fails without either while `/tmp` is `noexec` — the exact failure the
  `Dockerfile` now avoids.
- `node-pty` and the prebuilt addon load with `--ignore-scripts`; every dsh
  package's `engines` is satisfied by the pinned Node 24.13.0.

## Notes / gotchas

- `/tmp` is `noexec` because Docker's `tmpfs` default applies; the agent's
  workspace mounts remain executable, so only the loader copy needed relocating.
- `$DSH_HOME` is a writable named volume, but the agent's file sandbox
  (`workspace-write`) denies agent writes there. That is deliberate: the harness
  process and Web UI own sessions, credentials, settings, and profile patches;
  the agent only writes the mounted workspace.
- `--expose-internals` is no longer strictly required (the native binding is a
  fallback), but the `dsh-prod` wrapper keeps passing it as the built-in path.
- To bump again: edit `package.json`, run `pnpm install`, rebuild.
